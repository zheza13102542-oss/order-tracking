# ติดตามออเดอร์ (Order Tracking Page)

หน้าเว็บสำหรับให้ลูกค้าตรวจสอบสถานะงานด้วยหมายเลขออเดอร์ พัฒนาด้วย **Next.js 14 (App Router) + TypeScript + Tailwind CSS**

โจทย์กำหนดแค่ว่าเป็น "ออเดอร์" ผมเลยเลือกวางบริบทให้ชัดเป็น **โรงพิมพ์/งานผลิตสิ่งพิมพ์** เพราะสถานะที่โจทย์ให้มา (อยู่ในคิว → กำลังดำเนินการ → เสร็จสิ้น) คือลักษณะของคิวงานผลิต ไม่ใช่การจัดส่งพัสดุ ทุกข้อความบนหน้าเว็บจึงเขียนจากมุมของลูกค้าโรงพิมพ์จริง

---

## รันโปรเจกต์

ต้องมี Node.js 18.17 ขึ้นไป

```bash
npm install
npm run dev      # เปิด http://localhost:3000
```

คำสั่งอื่น

```bash
npm run build    # build production
npm start        # รัน production build
```

Deploy บน Vercel ได้ทันทีโดยไม่ต้องตั้งค่า environment variable เพิ่ม

| หมายเลข | ผลลัพธ์ที่ได้ |
|---|---|
| `ORD-2587965432159-458` | เจอออเดอร์ สถานะ **กำลังดำเนินการ** |
| `ORD-2587965432160-102` | เจอออเดอร์ สถานะ **รอชำระเงิน** |
| `ORD-2587965432161-771` | เจอออเดอร์ สถานะ **อยู่ในคิว** |
| `ORD-2587965431884-219` | เจอออเดอร์ สถานะ **เสร็จสิ้น** |
| `ORD-9999999999999-999` | Empty / Not found state |
| `ORD9999` หรือ `abc123` | Error state: รูปแบบไม่ถูกต้อง |
| `ORD-0000000000000-000` | Error state: เซิร์ฟเวอร์ตอบ 500 |

## ทำอะไรไปบ้าง (ตาม Requirements)

**1. ส่วนค้นหา** — ช่องกรอกพร้อมปุ่มค้นหา กด Enter ได้ มีปุ่มล้างค่าในช่อง และ helper text บอกรูปแบบ `ORD-` ตามด้วยตัวเลขพร้อมตัวอย่างจริง เมื่อกรอกผิดรูปแบบ helper text จะเปลี่ยนเป็นข้อความเตือนที่จุดเดิม ผู้ใช้ไม่ต้องกวาดสายตาหาว่าพลาดตรงไหน

ตรวจรูปแบบด้วย `/^ORD-\d{4,}(?:-\d{1,6})?$/` และ normalize เป็นตัวพิมพ์ใหญ่ก่อนเสมอ ลูกค้าพิมพ์ `ord-...` ตัวเล็กก็ค้นเจอ

**2. Status Badge System** — คอมโพเนนต์เดียว (`StatusBadge`) รองรับครบ 4 สถานะ สีกับข้อความอยู่ในไฟล์ `src/lib/status.ts` ที่เดียว เพิ่มสถานะใหม่แก้ที่นี่จุดเดียว แต่ละสถานะแยกกันด้วย **สี + จุดสี + ข้อความ** ไม่ใช้สีอย่างเดียว คนตาบอดสีจึงยังอ่านออก และมีแถบสีที่ขอบซ้ายของการ์ดช่วยให้กวาดตาหาสถานะจากรายการยาว ๆ ได้เร็ว

**3. รายการออเดอร์ + Tabs** — แยก "ออเดอร์ปัจจุบัน" กับ "ออเดอร์ที่ผ่านมา" โดยตัดสินจากฟิลด์ `active` ของสถานะ ไม่ใช่ hardcode ชื่อสถานะไว้ในหน้า แต่ละรายการมี Order ID (ฟอนต์ monospace ให้ตัวเลขตรงหลัก) ปุ่มคัดลอกที่มี fallback สำหรับเบราว์เซอร์เก่า วันเวลาในรูปแบบ `21/08/2026 15:42 น.` และ Status Badge กดดูรายละเอียดจะเห็นรายการสินค้าและ timeline ความคืบหน้า

**4. Responsive** — Mobile (360px ขึ้นไป): เรียงเป็นคอลัมน์เดียว ปุ่มค้นหาเต็มความกว้าง badge กับราคาย้ายมาชิดซ้าย Desktop: ปุ่มค้นหาอยู่ข้างช่องกรอก รายละเอียดแตกเป็นสองคอลัมน์โดยมี timeline อยู่ขวา

**5. State & Interaction**
- *Loading* — skeleton ที่มีรูปทรงเท่าการ์ดจริง หน้าไม่กระตุกตอนข้อมูลมา พร้อม `aria-busy` สำหรับ screen reader
- *Empty* — แยกข้อความตามแท็บ และเขียนแบบชวนให้ทำอะไรต่อ ไม่ใช่แค่บอกว่า "ไม่มีข้อมูล"
- *Error* — แยก 3 กรณีคนละข้อความ: รูปแบบผิด / ไม่พบออเดอร์ / เซิร์ฟเวอร์ล่ม กรณีเซิร์ฟเวอร์ล่มมีปุ่มลองใหม่ที่ยิง request ซ้ำจริง

## โครงสร้างโค้ด

```
src/
├─ app/
│  ├─ layout.tsx            metadata + ฟอนต์ + globals
│  ├─ page.tsx              โครงหน้า (header / main / footer)
│  ├─ globals.css           Tailwind + design token
│  └─ api/orders/route.ts   API จำลอง มี delay ให้เห็น loading state
├─ components/
│  ├─ OrderTracker.tsx      ศูนย์กลาง state ทั้งหมดของหน้า
│  ├─ SearchBar.tsx         ช่องค้นหา + validate ฝั่ง client
│  ├─ Tabs.tsx              แท็บ (role=tablist ตาม ARIA)
│  ├─ OrderCard.tsx         การ์ดออเดอร์ + ส่วนรายละเอียดที่พับเก็บได้
│  ├─ OrderTimeline.tsx     เส้นทางเดินของงาน 5 ขั้น
│  ├─ StatusBadge.tsx       ป้ายสถานะ ใช้ซ้ำได้ทุกที่
│  ├─ StatusLegend.tsx      คำอธิบายความหมายของ 4 สถานะ
│  ├─ CopyButton.tsx        ปุ่มคัดลอก + fallback
│  └─ States.tsx            Loading / Empty / Error
└─ lib/
   ├─ types.ts              TypeScript types กลาง
   ├─ status.ts             นิยาม 4 สถานะ (สี ข้อความ การจัดกลุ่ม)
   ├─ format.ts             regex ตรวจรูปแบบ + จัดรูปแบบวันที่/เงิน
   └─ orders.ts             ข้อมูลจำลอง
```

**หลักที่ยึด:** คอมโพเนนต์ที่ไม่ต้องใช้ state เป็น Server Component หมด (`StatusBadge`, `OrderTimeline`, `StatusLegend`, `States`) ส่วนที่ต้องมี interaction เท่านั้นที่เป็น `"use client"` ทำให้ JavaScript ที่ส่งไปหาผู้ใช้เหลือ ~6 kB

## แนวคิดการออกแบบ (Design Decision)

**ทำไมหน้าตาเป็นแบบนี้** — หน้านี้ไม่ใช่หน้าขายของ ผู้ใช้เข้ามาเพื่อหาคำตอบเดียวคือ "งานฉันถึงไหนแล้ว" ดีไซน์จึงใช้ภาพของ *กระดานคิวงานในโรงพิมพ์*: พื้นหลังกรมเข้มมีเส้นตารางจาง ๆ ในส่วนค้นหา แล้วปล่อยส่วนรายการให้เป็นการ์ดขาวสะอาดอ่านง่าย ความเข้มทั้งหมดของหน้าถูกใช้ไปกับส่วนค้นหาที่เดียว เพราะมันคือสิ่งแรกและสิ่งเดียวที่ผู้ใช้ต้องทำ

| Token | ค่า | ใช้ที่ |
|---|---|---|
| Paper | `#EAEDEF` | พื้นหลังหน้า |
| Ink | `#131A21` | ตัวอักษรหลัก |
| Muted | `#5C6B78` | ตัวอักษรรอง |
| Navy / Navy deep | `#123A5A` / `#0C2840` | ปุ่มหลัก, ส่วนค้นหา |
| Line | `#D6DCE1` | เส้นคั่น ขอบ |

สีสถานะ — อยู่ในคิว `#6B8296` / กำลังดำเนินการ `#1478D4` / เสร็จสิ้น `#17976D` / รอชำระเงิน `#D4820F`

ฟอนต์ **IBM Plex Sans Thai** สำหรับข้อความ (มีน้ำหนักครบและอ่านไทยปนอังกฤษได้สวย) และ **IBM Plex Mono** เฉพาะเลขออเดอร์ ราคา และเวลา เพราะเป็นข้อมูลที่ผู้ใช้ต้องอ่านทีละหลักและเทียบกับกระดาษในมือ

## สิ่งที่ยังทำต่อได้

- เชื่อมฐานข้อมูลจริงแทน `src/lib/orders.ts` โดยแก้เฉพาะใน `route.ts` ฝั่ง UI ไม่ต้องแตะ
- Deep link `?code=ORD-xxx` เพื่อให้แชร์ลิงก์ผลการค้นหาได้
- ปุ่มไปหน้าชำระเงินสำหรับออเดอร์สถานะ "รอชำระเงิน"
- แจ้งเตือนทาง LINE เมื่อสถานะเปลี่ยน
